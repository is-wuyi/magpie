What the relay does

Only the capabilities this deployment serves: a key-based relay with tenant isolation, scoped keys and prepaid billing.

Your own upstreams

Register keyed providers and magpie forwards requests with your credential. Keys are encrypted at rest and never drawn again.

Tenant isolation

Each provider belongs to one user or one house channel. Requests resolve only the models the caller is allowed to see.

Scoped API keys

Issue gateway keys limited to models, house channels, an expiry date and a concurrency cap. The secret is shown once.

Routing groups

Name a list of provider and model targets and route over it in order, failing over when one upstream cannot serve.

Wallet and house channels

Use channels the operator publishes, priced per model. Requests reserve and settle against a prepaid balance with per-attempt holds.

Recharge when enabled

Where the operator turns payments on, top up by Alipay or WeChat Pay. The balance and every hold are visible in the portal.

Safe by default

Outbound addresses are checked at the socket. Loopback, private, link-local and metadata targets are refused unless the operator allows them.

Runs on PostgreSQL

The cloud service ships in the same binary, behind Docker and a PostgreSQL store. Migrations apply at startup.

From account to first request

Three steps, no local install.

  1. 1

    Create your account

    Verify your email address, then choose a password. If registration is closed, ask the operator for an account.

  2. 2

    Add a provider or a channel

    Bring your own upstream key, or add a house channel the operator published. Nothing else on the machine is touched.

  3. 3

    Create a gateway key

    Pick the models and channels it may use, then point any compatible client at this address with that key.

Where the boundary is

magpie cloud is a relay, not a vault: it sees the requests it forwards. These are the limits it enforces.

  • Upstream credentials are encrypted with the deployment's configuration key and are never returned to a page.
  • Every read and write is scoped to the session's account; administrators act through the same server-side checks.
  • Outbound provider addresses are resolved and checked before connecting; private and metadata ranges are refused by default.
  • Gateway keys and email codes are stored as hashes. A new gateway secret is shown once and cannot be read again.
  • Cloud mode serves the relay and its portal only. Local agents, sessions, library, memory, MCP, plugins and subscription rotation are not enabled.
