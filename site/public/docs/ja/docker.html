Docker で magpie Cloud を運用する

メールコードで登録・ログインし、自分の API キー型プロバイダーと、管理者が公開したハウスチャンネルを使えるマルチユーザーリレーです。モデルごとの価格と前払いウォレットに対応します。

Cloud モードは旧来の単一管理者コンソールではありません。 Agents、Sessions、Library、Memory、MCP、OAuth プロバイダー、任意のプラグインは利用できません。PostgreSQL が必須です。
タグlatest（最新リリース）、daily（毎日 20:00 UTC）、stable（週 1 リリース）、0.1.1150（単一リリース）、0.1、edge（main の各変更）

起動

cp .env.example .env
# データベース、認証・暗号化キー、管理者メール、公開 HTTPS URL、SMTP を設定
docker compose up -d --build
docker compose ps
docker compose logs magpie

MAGPIE_AUTH_SECRET は 32 バイト以上の乱数、MAGPIE_CONFIG_KEY は 32 バイトちょうどの base64 または hex です。データベースパスワードは別に生成し、.env はコミットしないでください。管理者は MAGPIE_ADMIN_EMAILS のアドレスでメール認証を完了したユーザーだけです。

決済

Alipay には ALIPAY_APP_ID、アプリの秘密鍵と Alipay の公開鍵を設定します。WeChat Pay にはアプリ ID、店舗 ID、証明書シリアル、秘密鍵、32 バイトの API v3 キー、プラットフォーム証明書を設定します。どちらも未設定なら充值は無効ですが、他の機能は動きます。

コールバックは /api/payments/alipay/notify と /api/payments/wechat/notify を HTTPS で公開します。署名、店舗、アプリ、注文番号、通貨、金額を検証し、DB の行ロックと一意なイベント ID で二重入金を防ぎます。必ず実際の少額決済と再送テストも行ってください。

公開前の確認

  • 信頼できるリバースプロキシで HTTPS を終了し、PostgreSQL と 3425 を公開しないでください。
  • プロバイダーへの接続は、DNS 解決後の実際のアドレスで、プライベート・ループバック・メタデータアドレスを拒否します。VPC 内の管理された上流だけに MAGPIE_ALLOW_PRIVATE_UPSTREAMS=1 を設定できます。
  • 各ハウスモデルに明示的な価格を設定します。不明な価格は拒否され、明示的なゼロだけが無料です。
  • 2 人の一般ユーザーで、プロバイダー、モデル、グループ、Usage、API キーが分離されることを確認します。
  • 実際の PostgreSQL、SMTP、Alipay、WeChat のテストを行います。オフライン fixture だけを本番検証とみなさないでください。

データベースがユーザー、チャンネル、残高、注文、監査の正本です。定期的なバックアップとポイントインタイム復旧を設定してください。マイグレーションは番号順・トランザクション・チェックサム付きで実行され、変更や欠番、将来のスキーマを検出すると起動を拒否します。
