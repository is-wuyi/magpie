使用 Docker 部署 magpie 云

部署一个多用户中转站：用户通过邮箱验证码注册登录，可以添加自己的密钥型渠道，也可以添加管理员发布的本站渠道，充值后按模型价格使用。

这是新的多用户云端模式，不是旧的单管理员网页控制台。 Agents、Sessions、Library、Memory、MCP、订阅/OAuth 渠道和任意插件安装均不开放。必须使用 PostgreSQL。不要把旧的 MAGPIE_WEB_KEY 管理页面暴露给用户。
标签latest（最新发布）、daily（每天 20:00 UTC）、stable（每周一个版本）、0.1.1150（单个版本）、0.1、edge（main 的每次变化）

启动

仓库提供 compose.yaml 和 .env.example：

cp .env.example .env
# 修改 .env：数据库密码、认证密钥、配置加密密钥、管理员邮箱、
# 公网 HTTPS 地址和 SMTP 均为必填。
docker compose up -d --build
docker compose ps
docker compose logs magpie

MAGPIE_AUTH_SECRET 至少 32 个随机字节，MAGPIE_CONFIG_KEY 是恰好 32 字节的 base64 或 hex 编码。可使用 openssl rand -hex 32 和 openssl rand -base64 32 分别生成，数据库密码必须另行生成。不要提交 .env。

打开 MAGPIE_PUBLIC_URL。管理员邮箱完成验证码验证后才获得管理员权限，其他注册用户都是普通用户。用户可以维护自有渠道和 API 密钥、添加本站渠道、充值和查看余额；管理员可以维护上游密钥池、模型价格、发布状态、用户、订单、人工充值和审计。

必须配置

  • MAGPIE_DATABASE_URL：PostgreSQL 连接地址，Compose 会根据 POSTGRES_PASSWORD 生成。
  • MAGPIE_AUTH_SECRET：验证码和会话的 HMAC 密钥。
  • MAGPIE_CONFIG_KEY：上游 provider 配置的 AES-GCM 密钥，更换后旧密文将无法读取。
  • MAGPIE_ADMIN_EMAILS：逗号分隔的管理员邮箱白名单。
  • MAGPIE_PUBLIC_URL：公网 HTTPS 地址，也用于支付回调。
  • MAGPIE_SMTP_*：登录验证码邮件所需的 SMTP 服务。
  • MAGPIE_RECHARGE_PRESETS：服务端控制的人民币充值档位，浏览器不能自行指定其他金额。

支付宝与微信支付

没有配置任何支付商户时，充值功能关闭，其他功能照常运行。只要配置了支付宝或微信其中一种，就会严格校验该项配置。

  • 支付宝：ALIPAY_APP_ID、ALIPAY_PRIVATE_KEY、ALIPAY_PUBLIC_KEY，可选 ALIPAY_SELLER_ID 和 ALIPAY_GATEWAY_URL。使用电脑网站支付和 RSA2 异步通知验签。
  • 微信支付：WECHAT_APP_ID、WECHAT_MCH_ID、WECHAT_MERCHANT_SERIAL、WECHAT_PRIVATE_KEY、32 字节 WECHAT_API_V3_KEY 和 WECHAT_PLATFORM_CERTIFICATES。使用 API v3 Native，返回用于微信扫码的 code_url。

回调路径为 /api/payments/alipay/notify 和 /api/payments/wechat/notify，必须通过公网 HTTPS 直接访问，不能跳转到登录页。入账前会验签并检查商户、应用、订单号、币种和金额，数据库行锁和唯一事件号保证重复回调不重复入账。离线签名测试不能替代每种商户的一笔真实小额支付和重复回调验证。

公网安全

  • 使用可信反向代理终止 HTTPS，只在代理会覆写转发头时开启 MAGPIE_AUTH_TRUST_PROXY_HEADERS。不要公开 PostgreSQL 和 3425 端口。
  • 每个本站模型都必须有明确的当前价格；未知价格会拒绝请求，只有显式零价才表示免费。价格修改只影响新预扣。
  • 上游拨号默认拒绝内网、loopback、链路本地和云元数据地址。只有管理员自己的上游确实位于 VPC 内网时，才设置 MAGPIE_ALLOW_PRIVATE_UPSTREAMS=1。
  • 上线前用两个普通用户验证渠道、模型、路由组、Usage 和 API 密钥互不可见，确认本站上游密钥不会出现在响应或日志中。
  • 必须运行真实 PostgreSQL 并发、重启和升级迁移测试，以及真实 SMTP 和商户回调测试，不能只用离线测试代替。

备份与升级

数据库是用户、渠道、余额、订单和审计的事实数据源，请使用 PostgreSQL 定期备份和时间点恢复。/config 只保存运行时缓存，不是资金账本。迁移按编号、事务和校验和执行，遇到校验和变化、版本缺口或更新版本的数据库会拒绝启动。升级前备份，然后运行 docker compose up -d --build。停止用 docker compose down；不要在未确认要删除全部数据时使用 down -v。

GET /api/cloud/health 检查数据库和 provider 存储。后台任务会根据预扣 ID 恢复用量并结算，只有确认没有可用用量时才退款；读取失败会保留预扣，不会盲目退款。支付后入账失败的订单会按 credit_state 重试，重复回调不会重复加余额。
